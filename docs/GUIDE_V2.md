# LaserClaw 2.0 使用指南

## 当前推荐工作流

1. 在首页选择 **API Key** 或 **Codex exec**。Codex模式使用后端所在电脑的官方CLI和ChatGPT登录，默认 `gpt-6.1-sol`；刷新登录状态、测试连接后保存。完整步骤见 [Codex exec配置](CODEX_EXEC.md)。
2. 新建案例只填标题与描述。在 **Agent工作区** 提出任务，提供已有信息、已搭光路、元件和附件；不必先猜出整张设计参数表。
3. Agent按任务读取案例、库存与旧结果，建立模型、计算、扫描、比较并保存。查看 **工具过程** 可核对每次真实输入输出；模型服务失败时已完成的计算保留。
4. 在 **光学工程** 查看当前版本：物理位置、介质和掺杂段边界、半径曲线、束腰及截面光斑。可切换半径／直径、μm／mm、显示范围；CSV／SVG／PNG直接导出。展开结果区可获得完整图表宽度。
5. 在 **光场与扫描** 切换不同朝向、冷热腔及扫描记录；二维图明确显示轴参数、单位、T/S稳定指标与无效点。不同场景不会覆盖彼此。
6. 工程编辑器可增删元件、修改自由参数、保存新版本和二维扫描。已有硬件参数有锁定约束，历史工程继续保留。报告和概览优先使用最新工程；原始参数保留为来源记录。
7. 当结果为“部分完成”或“需要补充”时，按问题附带的方法和单位提交数据。几何稳定不等于真实出光，更不等于最高效率；目前没有增益饱和、输出功率、空间热场或复合腔求解器。

通用工具支持单程、驻波腔和共面环形腔、T/S像散、薄／厚透镜、GRIN、ABCD矩阵、实测焦散和功率曲线拟合。当前运行Python/NumPy内核，尚未接入Rezonator C++。详见 [工具能力与边界](WORKBENCH.md) 和 [真实案例验收](releases/2.0.0/README.md)。

以下章节保留早期开发阶段及专用平凹腔模块的操作记录；其中v3.x为未发布的开发标记，专用模块限制不代表上述通用工作区的全部能力。

> 面向实验室日常使用者。想看代码结构请转 [ARCHITECTURE.md](ARCHITECTURE.md)。

## v3.3：围绕任务选择工具

新建案例仍然只填标题与描述，创建后进入 **Agent 工作区**。可以提出不同类型的任务：设计光路、复核已有方案、匹配元件、分析实测数据、比较选择、查资料或排查现象。无需先选择某个物理模块。

Agent 会读取已有信息、选择工具、查看工具结果，再决定下一步。它能组合多种工具，也能在工具报错时改正输入。缺参时会解释这个参数影响什么、怎样测量或查到，以及回复的单位与格式。直接在同一输入框补充，便可继续推进。无法完成的部分会保留为部分结果或明确的能力边界，不会自动包装为“完成”。

- **任务结果**：结论、事实来源、假设、需要补充的信息、后续建议和实际计算图。
- **工具过程**：每一步的目的、真实输入输出、错误和耗时；可下载完整 JSON 记录。
- **已存光路设计**：保留已有平凹腔设计版本与 v3.2 精细分析台。它是可调用的专用能力。
- **停止 / 继续**：停止后保存已经执行的结果；正在执行的单次调用需要先结束。回复或点击继续便能复用此前记录。

当前一般光学工具支持近轴单程、驻波和共面环形系统的 T/S 计算及参数扫描。运行内核是 Python / NumPy ABCD，尚未连接 Rezonator C++ 程序；三维热场、应力、寿命、激光输出功率全局优化不在其计算范围内。参见 [任务工作区能力与架构](WORKBENCH.md)。

下面的 v3.1 / v3.2 章节记录保留的专用光路设计能力；新任务统一从 Agent 工作区提出，旧设计图表在“已存光路设计”中查看。

## v3.1：从目标、已有元件与库存求解光路

1. 首页配置 Agent。当前可填 `gpt-6.1-sol`，使用已配置的 OpenAI API Key；读图需要所选模型支持图片。
2. **新建案例**只填标题与描述 / 备注，创建后直接进入**实验设计**。
3. 直接按案例标题 / 描述开始设计，也可补充目标、已有元件或上传标签。展开**已有元件 / 固定位置 / 设计约束**绑定库存、锁定已经安装的主面坐标、M1 间隙或输出镜曲率。留空的设计变量交给求解器，缺失器件由库存或采购方案补齐。
4. 右侧首先给出 M1 到晶体前端面、晶体后端面到 M2 的距离，再列出候选、光学分析台、所有元件坐标和补齐清单。在分析台输入 M2 间隙或点击稳定性曲线可直接重算；点击**将此间隙用于新设计**生成独立的新版本。
5. 在同一个输入框补充或纠正参数，例如“准直镜实测焦距为 100 mm”。每次更新保留旧版本。点击问题卡可定位输入；计算失败可恢复上次输入，已保存的版本不受影响。
6. 导出坐标 CSV、腔镜选型 CSV、**Rezonator 冷腔 .rez**，或通过案例页“导出打包”保存版本 ZIP。.rez 使用全部晶体物理长度和折射率，导出驻波冷腔，不含泵浦和热透镜场景。库存是计算当时的快照，借还、导入后重新计算可刷新。

### v3.2：精确查看仿真结果

- 点击**展开分析台**获得完整绘图区。可查看束宽、对称包络、波前曲率 1/R、波前半径 R、M2 稳定性扫描；图面支持框选缩放、平移、图例隐藏和双击复位。
- **晶体 / 掺杂段 / 束腰 ±2 mm**提供局部视野，也能输入任意 z 范围。纵轴可切换 μm / mm、半径 / 直径；均以 1/e² 强度定义。泵浦束腰局部视野优先定位晶体内焦点。
- **精确游标**允许输入任意 z，直接由分段 ABCD 传播求出 w、R、q 和 n，不对绘图点插值。界面 / 薄透镜处取出射侧，光路终点取内侧；关键截面表同时保留界面两侧数据。
- 绘图密度可选 300 / 900 / 2400 点，并自动加入介质边界、解析束腰及其附近的加密点，避免窄泵浦束腰被均匀采样漏掉。小数位表示计算精度，不等于实物测量精度。
- 改 M2 间隙、热透镜焦距只做即时预览，不调用 LLM，不改动已保存坐标；需采用新间隙时生成新版本。热腔图同时显示同间隙的冷腔参考。无稳定本征模时明确显示无解，不补画虚构光束。
- **数据 CSV**导出当前模式的全部传播点，稳定性视图则导出各热焦距的扫描原始值；**SVG / PNG**导出当前图形。稳定性纵轴初始为 ±1.5，底层数据没有截断，可缩放看全。
- 当前分析采用轴对称标量模型，T=S。尚无任意腔型编辑、T/S 像散分离、双折射走离或完整三维热模型。对照 Rezonator 的 `CausticFunction.cpp`、`AbcdCalculator.cpp` 和上游参考计算校验，不宣称完整功能等同。

### 数值模型的范围

- 当前对话式设计求解器支持端泵直线腔，采用平面输入镜与凹面输出镜，扫描曲率、物理腔长、晶体位置。环形 / 折叠腔会提示当前模型不适用。
- ABCD 传播保留晶体前后平面折射和完整物理长度。复合晶体端帽参与光程；阈值增益只使用掺杂段长度。
- 内置 YVO4 折射率取自 [CRYSTECH Sellmeier 数据](https://www.crystech.com/Laser_Crystal/446.html)，π 偏振和相同端帽折射率作为明示假设，不能替代具体晶体证书。
- 冷腔按 1/e² 强度半径画图。热透镜扫描在晶体几何中心插入薄透镜并往返两次，是场景敏感性分析，不是由泵浦瓦数推得的热模型。
- 光纤泵浦采用薄透镜共轭成像，默认镜间距 f1+f2；已经固定的准直段位置可以改变镜间距。R50 且材料未知时，按明示的 N-BK7 假设推出焦距，约 98 mm。位置不依赖芯径和 NA，缺失这些参数仍给名义坐标；包络使用明示的芯径 / NA 场景。SM9/125 等标签不等同于实测 808 nm 模场。主面、像差、M1 基底厚度和实际填充率需要实物校准。
- 模式目标未知时，以 150 μm 为探索假设。搜索对全部可行离散几何评分，再保留不同曲率的优选项。输出镜默认 T=5% 起始方案，可采用匹配库存的真实 T，同时给 1/3/5/10% 阈值增益比较。页面的“综合最优候选”指给定范围、目标和假设下的排序第一；最大输出功率和效率尚需吸收、增益、损耗模型。
- 当前运行的是独立实现的 Python / NumPy ABCD 内核，仓库附带 Rezonator 源码并不表示正在运行其 C++ 程序。回归测试使用 Rezonator 自带 `calc/rezonator.py` 校验导出冷腔的稳定参数与束宽。
- 镀膜按明确波段匹配。AR880 不等于 AR808。库存排除损坏和无可用数量的器件，缺失规格列为待核验；空库给采购规格，不捏造已有器件。

## 0. v2.0 变了什么

**v1 是"会查资料、会写文档的 AI 助手";v2 是"会算物理、认识你实验室元件的工程伙伴"。**

v1 里所有结论都来自大模型的语言生成——包括那些看起来像数字的部分。v2 引入了一层**确定性物理内核**:谐振腔、相位匹配、镀膜、功率曲线全部由公式算出来,LLM 只负责理解你的需求、编排工具、解释结果。

核心原则(贯穿整个 v2):

| | 谁来做 | 为什么 |
|---|---|---|
| 物理量(角度、束腰、阈值、反射率) | **确定性计算** | 大模型会非常自信地编一个看起来合理、实际错误的数字,你根本看不出来 |
| 取舍判断(差一点能不能凑合) | LLM + 你 | 但必须**站在算好的数字上**,不是拍脑袋 |
| 最终拍板 | **你** | 系统给的是可审计的依据,不是命令 |

还有一条贯穿全篇的态度:**不知道就说不知道**。系统宁可告诉你"需实测",也不会给你一个编造的数。

## 1. 启动

**前置要求**(只需装一次):

- [Python 3.11+](https://www.python.org/downloads/)——安装时务必勾选 "Add python.exe to PATH"
- [Node.js 22 LTS](https://nodejs.org/)

装好后双击仓库根目录的 **`Launch-LaserClaw.bat`**。它会检查环境、装依赖、起后端(:8000)和前端(:5173)、等服务就绪后自动开浏览器。关掉弹出的两个黑窗口即停止。缺 Python/Node 或安装失败时,窗口会用中文告诉你原因并停住(不会闪退)。

**首次运行会自动生成配置文件 `.env`**(在仓库根目录,记事本就能打开)。没配模型 key 时是演示模式:页面顶部会有黄色横幅提醒「演示模式」,此时 AI 输出全是固定模板,物理计算不受影响。

### 在首页配置 Agent（v2.3 新增）

首页 → **Agent 配置** → 选择模型服务商 → 选择或填写模型 ID → 粘贴 API Key → **保存并应用**。

- API Key 默认隐藏，点击「显示／隐藏」切换本次输入的可见性。保存后输入框会清空，已有密钥不会回显；以后只改模型时，密钥留空即可沿用。
- 支持 DeepSeek、通义千问、智谱 GLM、Kimi、OpenAI 兼容接口和 Anthropic Claude。模型 ID 支持手动填写，以服务商实际开放给账号的模型为准。
- 使用兼容服务或代理时，展开「高级设置 · 接口地址」填写 Base URL；填基础 API 路径，不含 `/chat/completions`。
- 保存后下一次 Agent 对话、计划、排查和报告生成即使用新配置，无需重启。保存成功表示本地配置已写入，密钥权限与模型可用性在实际调用时验证。
- 配置保存在后端 `UPLOAD_DIR/.agent-settings.json`，启动器默认放在 `%USERPROFILE%\LaserClaw-Data\uploads`，随数据目录保留。文件包含密钥，不应提交到代码仓库。首页保存的字段优先于 `.env`；未保存过的字段继续使用 `.env`。切换服务商会保留各自已保存的密钥与模型。

### 通过 `.env` 配置模型（可选）

用记事本打开根目录的 `.env`(首次启动已自动生成),设置(四选一):

```
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-你的key
```

可选值:`deepseek`(深度求索)、`qwen`(阿里通义千问)、`zhipu`(智谱 GLM)、`moonshot`(月之暗面 Kimi),另外仍支持 `openai` / `anthropic` / `mock`。

**强烈建议同时加一行**:

```
STRICT_PROVIDER=true
```

否则 key 配错时系统会**静默回退到 mock 假数据**,你会以为在用真模型。开了这个开关就会直接报错。

> v2.0 起,无论从哪个目录启动后端,都会正确读到仓库根目录的 `.env`(以前从 `backend/` 启动会读不到,导致**明明配了 key 却静默用 mock 假数据**)。
> `.env` 里的 `DATABASE_URL` 现在是本地 SQLite;Docker 部署时 compose 会注入自己的数据库地址并自动覆盖,无需改动。

## 2. v2.0 新增功能全览

### 2.1 元件库(全新页面)

**解决的问题**:以前 AI 给你出实验方案,不知道你实验室实际有什么;现在它知道。

**怎么用**:

1. 导航栏 → **元件库** → 选择你的元件清单 xlsx(如"127镜片统计")→ 导入
2. 系统会把每一行的**镀膜字符串拆解成结构化数据**。比如
   `S1:1064-1066HR, 1176-1180 T=20%`
   会被拆成两条记录:`S1 面 / 1064–1066nm / HR` 和 `S1 面 / 1176–1180nm / 部分透过 20%`
3. 导入完成会显示三个数字:**导入条目 / 镀膜段 / 待复核**

**关于"待复核"**:凡是系统读不懂或你自己写了"切向未知""不能确定是否镀膜"的行,都会进这个队列,**原始文字完整保留**。勾选筛选区的"待复核队列"就能只看这些。系统绝不会替你猜。

**筛选**:可以按 `波长 + 功能` 精确筛(这是数据库级查询,不是关键词搜索)。比如填 1064 + HR,只会给你在 1064nm 真正是高反的镜子——而不是"名字里带 1064"的镜子。

### 2.1.5 借出 / 归还 / 标损坏

元件表最后一列是**借用 / 状态**,解决的是"这块镜子明明在库里、上台一找发现在别人手上"。

- **借出**:点「借出」→ 填谁拿走了(本地版没有登录,名字就是唯一的线索)→ 可选填用途。
  数量列会变成 `可用 / 总数`(比如 `2 / 3`),行里出现一个「张三 ×1」的标签和「归还」按钮。
- **归还**:点「归还」→ 确认 → 系统会**顺便问一句"有没有损坏"**。归还时才是真正发现损坏的时刻,
  不必再去找一个单独的入口。归还记录**不会删**,以后要查"上次坏掉时是谁在用"能查得到。
- **标损坏**:随时可以标,可以写一句说明(鼠标停在「人工标记」标签上能看到)。

三件事必须知道:

1. **清单中元件的库存数量等于工作簿里写的数**。借出不去动它,可用量是算出来的。
   否则你下次重新导入 xlsx,借出账会被静默清掉、库存凭空变多。
2. **你标的损坏不会被重新导入冲掉**。人工标记和从表格文字里解析出来的状态分开存,人的判断优先。
3. **借出去的、标损坏的元件不会出现在匹配结果里**,淘汰理由会写明是「元件标注损坏」还是
   「可用数量不足(需 1,库存 3,已借出 3)」——不会给你推荐一块正躺在别人抽屉里的镜子。

**有元件没还的时候,既不能重新导入同一个文件,也不能删除这个批次**(都会提示"还有未归还")。
请先完成归还，避免新清单的数量或规格与正在借出的元件冲突。删除批次会连借用历史一起删除。

**同名文件重新导入会保留元件编号、人工损坏标记和已归还的借用历史。** 系统按名称与原始规格对应条目，
重复规格再按存放地、保管人、厂商区分，所以在 Excel 中排序不会把损坏标记转移给别的元件。
若带人工记录的条目无法对应，整次导入会取消并说明原因。最新清单中移除的条目若有人工状态或借用历史，
会保留在库中、数量置零；再次出现相同条目时沿用其原有记录。

### 2.2 元件匹配(按需求找元件)

**解决的问题**:"我要一块 1064 高反、曲率 400、口径至少 25 的镜子,库里有吗?"

在元件库页面填需求 → 开始匹配。系统对**每一件**库存逐参数判定,输出三类结果:

- **入围 / 前沿**:能用。"前沿"= 在所有维度上没有被其他候选全面超越的那几个,是你真正该在里面挑的
- **需实测**:可能能用,但依据不足。会明确告诉你**要测什么**
- **淘汰**:硬伤。页面底部会给"淘汰原因分布",让你知道是曲率不对、口径不够,还是镀膜不匹配

**三态判定是这套系统的精髓**,举个真实例子:

> 你需要 1064nm HR,库里有块标称 **1123nm HR** 的镜子。
> 系统不会简单说"不匹配",也不会假装能用,而是:调用薄膜物理内核算出这类镀膜的典型阻带约 1007–1269nm → 1064 落在里面,距离边缘 57nm → 判定 **"可能能用,需实测"**,并注明这是基于标准膜系的**物理先验,不是这块镜子的实测曲线**,上台前请测反射率。

反过来,如果某块镜子标称 **R=85%** 而你要求 R≥99.5%(在匹配表单的「反射率下限 R ≥ (%)」框填 99.5),系统会**直接淘汰**并说明"标称反射率 85% < 需求 99.5%"——不会因为"它也叫 HR"就放行。不填反射率下限时只按功能(HR/AR/PR)匹配,不做反射率硬判定。

### 2.2.5 实验计划会自己把腔设计出来(v2.0 关键能力)

**你不需要先知道用什么镜子。** 新建案例时,表单里有一块**「物理参数」区**——激光波长、增益晶体、腔镜曲率、倍频晶体都是现成的中文字段,不用记任何键名。**至少填「激光波长」**,生成实验计划时 LaserClaw 就会先跑确定性物理内核:

- 你**给了**腔镜曲率 → 扫描腔长,给稳区和推荐几何
- 你**没给** → 它**自己搜索**:遍历候选曲率 × 腔长(上千到上万种组合),两级排序挑出可实际搭建的几何。
  **候选曲率优先取自你导入的元件库**——不会推荐你没有的镜子。

**排序不看 |m|,而是实测热透镜裕度。** 这一点很重要:线性腔 `m = 2·g₁g₂ − 1`,所以 |m| 小
既可能是短臂分支、也可能是近共心分支,后者极不耐热透镜。实测方式是在增益介质处插一片薄透镜、
扫描光焦度直到失稳,报出腔能承受多少屈光度。同一对 R=400mm 镜子:

| 腔长 | 冷腔 \|m\| | 实测可承受热透镜 |
|---|---|---|
| 120 mm | 0.012 | **4.4 D** |
| 685 mm | 0.016 | **0.6 D** |

两者按 |m| 看几乎一样"安全",实际差 7 倍——所以旧的 |m| 判据被废弃了。

算出的数字会作为**权威数值**写进计划正文。真实例子(用户只说"想搭 808 泵浦 Nd:YAG 1064、
腔内 LBO 倍频到 532、输出 >1W,我只有库存里这几片镜子"):

> 推荐 R1=**R=500mm**、R2=**平镜**,腔长 **85.0mm**;冷腔束腰 **w0=0.24948mm**;
> 热透镜裕度 **8.3 D**(即 f≥120.5mm 时仍稳定)。
> 元件摆位:M1 @ **0.0mm** → 晶体入口 **20.0mm** → 晶体出口 **30.0mm** → M2 @ **85.0mm**。
> LBO type-I 1064→532 相位匹配:xy 面 **θ=90.0°, φ=11.36°**(另有 xz 面解 θ=32.48°)。
> 搜索空间:实验室库存曲率,评估 1413 种几何,其中 552 种稳定。

搜索过程可审计:计划页顶部会有一块绿框的**「物理内核计算结果」**,展示推荐几何、热透镜裕度、元件摆位、备选方案、搜索空间和边界提醒——这些是确定性计算,和 LLM 写的文字明确分开。如果内核没跑(比如没填波长),计划页会出现**红色警示**告诉你计划里的数字未经内核验证。
仍未纳入排序的因素——泵浦光斑与基模的重叠(模式匹配)、镀膜损耗、热透镜的像散与高阶项,这些仍需你上台核实。

### 2.3 物理计算模块(4 个)

在**案例 → 模块** tab,下拉框分成"测量分析"和"物理计算"两组。物理计算这 4 个都是纯公式,不经过大模型:

#### 谐振腔设计(cavity_design)
给腔镜曲率(和可选的晶体参数),它扫描腔长找出**稳定区间**,推荐一个腔长,并给出**每个元件从 M1 起的毫米级摆放位置**、各面光斑大小和**实测热透镜裕度**。

摆位表上方会画一张**摆位图**:M1、晶体、M2 按**真实横向比例**摆在一条光轴上,镜面的凹凸朝向就是实际朝向,
中间是冷腔基模的光束包络,束腰位置单独标出来。纵向(光斑半径)会**放大几百倍**才看得见——
放大倍数写在图下面那行小字里,不会让你把图上的粗细当成真实尺寸。
图里不含热透镜,是冷腔;这也写在图下的说明里。

推荐依据:填了目标束腰按束腰匹配;没填则按**实测热透镜裕度最大**(和实验计划的搜索一致,不用 |m| 代理判据)。

参数可以**完全留空**——自动读案例参数,腔长没给时自动扫描 30–800 mm。什么都没填时会用中文提示你至少要给腔镜曲率。也可以填:
```json
{"R1_mm":"flat","R2_mm":500,"L_scan_mm":{"start":100,"stop":600,"step":10},"target_waist_mm":0.25}
```

#### 相位匹配(phase_match)
算 SHG/SFG 的相位匹配角与走离,支持 BBO / LBO / KTP / BiBO。
```json
{"crystal":"lbo","lambda1_nm":1064,"pm_type":"I"}
```
和频(如 1064+532→355)加一个 `"lambda2_nm":532` 即可。

#### 镀膜评估(coating_tmm)
三种模式:知道膜系 → 精确算;有厂商曲线 → 直接用;**只有标称波长 → 给诚实的原型估计**(带阻带区间、置信度、"建议实测"标记)。
```json
{"nominal":{"function":"HR","design_wavelength_nm":1123},"query_wavelengths_nm":[1064]}
```

#### 元件匹配(component_match)
就是 2.2 的能力,挂在案例里,结果会存进案例的审计轨迹。

### 2.4 功率曲线(v2 新增的测量模块)

**这是你日常最常用的测量**:不同泵浦功率下的输出功率。

**怎么用**:加一个"功率曲线"模块 → 上传两列数据文件(泵浦, 输出),支持 `.csv` / `.txt` / `.tsv`,逗号/制表符/空格分隔都行。或者在参数里内联:
```json
{"output_coupler_T_pct":5,"label":"T=5% 输出镜","data":{"pump":[...],"output":[...]}}
```

**它会自动算出**:
- **阈值泵浦功率**和**斜率效率**(自动识别线性区,用整段折线拟合,不会被数据尾巴带偏)
- 带坐标刻度、实测数据点、阈值标记的拟合图

**跨曲线分析(重点)**:如果你给同一个案例测了**多个不同输出镜透过率**的曲线,并在参数里标了 `output_coupler_T_pct`,系统会自动做:
- **Findlay-Clay 分析** → 反推**腔内往返损耗**
- **Caird 分析** → 反推**本征斜率效率**

也就是说,你日常的例行测量数据,直接就能算出腔内损耗——这是以前要手动画图拟合才能得到的量。

**关于警告**:如果数据不是典型的阈值曲线(比如高低泵浦段斜率不一致 = 热翻卷),系统会**明确警告**而不是给你一个漂亮但错误的阈值。看到警告请认真对待。

### 2.5 Agent 现在会真的调用工具

以前在 Agent 里说"设计个腔",它会写一段文字。现在:

> 你说:**"帮我设计一个谐振腔,扫描腔长找到稳区,算出束腰和元件摆放位置"**
>
> 系统:识别意图 → 制定 4 步计划 → 检索知识库 → **调用腔设计工具真算** → 结果+引用存档

聊天里会显示三种标签:**路由到哪个工具**、**任务编号与状态**、**📎 引用了哪些文档**。案例的 Agent tab 里能看到完整轨迹:每一步、每个工具调用、耗时多少毫秒。**全程可回放、可审计。**

也可以在案例的 Agent tab 里直接从下拉选模式(谐振腔设计/相位匹配/镀膜评估/元件匹配/功率曲线分析等)。

### 2.6 文献检索(三个入口)

**解决的问题**:选晶体、查相位匹配角、找先例参数都要翻文献,以前得离开 LaserClaw 去各个网站搜。

数据来源是 **OpenAlex**(期刊元数据+摘要+被引数)和 **arXiv**(物理预印本),都免费、免注册、国内可直连。
三个入口,结果完全一致:

1. **导航栏 → 文献检索**:不用建案例,填检索词直接查。查完可以「存入案例」——会在那个案例里
   建一个文献检索模块并存档结果。
2. **案例 → 模块 → 文献检索**:和其他模块一样,检索词留空会自动用案例的波长/晶体拼一个;
   结果存档后**自动进入案例知识库**,之后生成实验计划/报告时可以引用到这些文献。
3. **Agent 对话**:直接说「帮我找几篇 LBO 相位匹配的文献」,系统会自动路由、把你句子里的
   主题词拿去检索,结果存到关联案例。

每条结果带标题(可点开原文)、作者、年份、期刊、被引数、摘要(折叠),支持一键**导出 BibTeX**
(写论文时直接粘进 .bib 文件)。

三件事必须知道:

- **检索词建议用英文**——激光领域的文献库以英文为主,中文词查 OpenAlex/arXiv 基本查不到东西。
- **查到 ≠ 读过**。系统拿到的是元数据和摘要,没有读任何论文全文;摘要只够初筛,采信结论请打开原文。
  这句声明会跟着结果一起显示(打印也在)。
- **中文文献(知网/万方)没有公开合法的接口**,系统不做爬虫。中文文献请在知网导出后自行整理,
  后续版本会支持 BibTeX/RIS 文件导入。

**Q:检索失败怎么办?** 每个源单独失败单独提示(比如 arXiv 连不上但 OpenAlex 正常,会给出
OpenAlex 的结果并注明 arXiv 失败了);全部失败会明确报错,不会假装"没有相关文献"。

## 3. 典型工作流:从零搭一个 1064 倍频腔

1. **新建案例** —— 填标题、腔型、目标,在「物理参数」区填**激光波长 1064**(其他能填就填:增益晶体 n/厚度、倍频晶体选 LBO 等;腔镜曲率不知道就留空)。保存后自动跳到案例详情页
2. **腔镜曲率留空的,先生成实验计划** —— 计划 tab → 生成。自动搜索只在这一步跑:系统遍历候选曲率 × 腔长,
   在绿色「物理内核计算结果」框里给出**推荐的 R1/R2 和腔长**。把推荐曲率记下来(想让后面的模块自动读到,
   也可以回「概览」把它填进腔镜曲率字段)。已经知道用什么镜子的,直接跳到第 3 步
3. **模块 → 谐振腔设计** —— 参数留空直接运行 → 拿到稳定区间、推荐腔长、摆位图与元件摆位
   (这个模块需要腔镜曲率:案例里填了就自动读,没填会用中文提示你——推荐曲率来自第 2 步)
4. **元件库 → 元件匹配** —— 用上面得到的曲率去库里找镜子 → 看哪些能用、哪些需实测
5. **模块 → 相位匹配** —— 确认倍频晶体的切角
6. **模块 → 镀膜评估** —— 核查候选镜子在 1064/532 各波长的表现
7. 上台搭建,把"需实测"清单上的项目测掉
8. **模块 → 功率曲线** —— 传测量数据,拿阈值和斜率效率;换个输出镜再测一条 → 自动出腔内损耗
9. **Agent → 生成实验报告** —— 所有模块结果和引用都在案例里,报告有据可依

**带进实验室**:在案例页按 `Ctrl+P`(Mac 是 `⌘+P`)→ 目标选「另存为 PDF」或直接打印。
导航栏、按钮、折叠区会自动去掉,白底黑字,摆位图和功率曲线是矢量的,放大不糊。
台子边上不一定有电脑,纸更靠谱。

## 4. 必须知道的边界(诚实清单)

这些不是 bug,是明确标注的适用范围:

- **双轴晶体相位匹配**(LBO/KTP/BiBO)用主平面近似,标注为 `medium` 置信度。下单前请和厂商确认切角
- **标称镀膜的阻带估计**是基于"标准膜系"的物理先验,**不是你那块镜子的实测曲线**。凡是标了"需实测"的,上台前请真的测
- **腔内有晶体时,束腰的"位置"是光程坐标**(尺寸精确)。要物理位置请看各面光斑列表
- **系统不控制任何硬件**。它是工作流与计算助手,不是控制系统
- **LLM 生成的文字部分**(实验计划、排故建议、报告)仍是启发式的,需要你判断。但**所有数字**来自确定性计算

## 5. 常见问题

**Q:参数框必须写 JSON 吗?**
不必。物理计算模块留空就能跑(自动读案例参数)。要覆盖时,点"参数示例"折叠区抄一条改。

**Q:元件库导入需要什么权限?**
本地默认部署(`REQUIRE_AUTH=false`)下直接可用,不需要任何操作。只有管理员开启了 `REQUIRE_AUTH=true` 的多人部署才需要 reviewer 账号。

**Q:元件库里"待复核"的行怎么办?**
那是系统读不懂或你原表就标了"未知"的行。原始文字都在，你可以在原 xlsx 里补全后重新导入。
如果该条目已有人工状态或借用历史，改变名称或规格可能触发“无法对应”提示；请核对这些身份字段，避免把历史记到另一件元件上。

**Q:改了文件名重新导入,元件变成两份了?**
是的——不同文件名会当成不同批次累加。在元件库页面的「导入批次」列表里删掉旧批次即可。

**Q:提示"还有未归还的元件",不让我重新导入?**
先把借出去的元件点「归还」，再导入。同名文件刷新会保留元件编号和历史，但必须先完成借出账目核对。

**Q:方案能打印或存成 PDF 吗?**
能。在案例页按 `Ctrl+P`(Mac `⌘+P`),选「另存为 PDF」。导航栏和按钮会自动隐藏,白底黑字,图是矢量的。

**Q:更新到新版本后要做什么?**
双击 `Launch-LaserClaw.bat` 就行,数据库会自动补上新版本加的字段,原来导入的元件和案例都在。
v2.2.1 还会修正旧附件路径，让迁移后的文件从数据目录读取。修正前的数据库备份为
`%USERPROFILE%\LaserClaw-Data\laserclaw.db.before-upload-paths.bak`。已有方案若需要使用本次修复后的检索证据，请重新生成。
(用 Docker 部署的多人版仍然按 `alembic upgrade head` 走。)

**Q:功率曲线要几条才能算腔内损耗?**
至少 2 条不同输出镜透过率的曲线。但 2 条时 R²=1 是数学必然、没有意义,系统会提示你"建议再测一组"。3 条起结果才可信。

**Q:界面能切英文吗?**
右上角 EN 按钮,全站双语。
