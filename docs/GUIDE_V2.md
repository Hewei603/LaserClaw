# LaserClaw v2.0 使用指南

> 面向实验室日常使用者。想看代码结构请转 [ARCHITECTURE.md](ARCHITECTURE.md)。

---

## 0. 一句话:v2.0 变了什么

**v1 是"会查资料、会写文档的 AI 助手";v2 是"会算物理、认识你实验室元件的工程伙伴"。**

v1 里所有结论都来自大模型的语言生成——包括那些看起来像数字的部分。v2 引入了一层**确定性物理内核**:谐振腔、相位匹配、镀膜、功率曲线全部由公式算出来,LLM 只负责理解你的需求、编排工具、解释结果。

核心原则(贯穿整个 v2):

| | 谁来做 | 为什么 |
|---|---|---|
| 物理量(角度、束腰、阈值、反射率) | **确定性计算** | 大模型会非常自信地编一个看起来合理、实际错误的数字,你根本看不出来 |
| 取舍判断(差一点能不能凑合) | LLM + 你 | 但必须**站在算好的数字上**,不是拍脑袋 |
| 最终拍板 | **你** | 系统给的是可审计的依据,不是命令 |

还有一条贯穿全篇的态度:**不知道就说不知道**。系统宁可告诉你"需实测",也不会给你一个编造的数。

## 1. 启动

双击仓库根目录的 **`Launch-LaserClaw.bat`**。它会装依赖、起后端(:8000)和前端(:5173)、自动开浏览器。关掉弹出的两个黑窗口即停止。

### 想用大陆模型(v2 新增)

在根目录 `.env` 里设置(四选一):

```
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-你的key
```

可选值:`deepseek`(深度求索)、`qwen`(阿里通义千问)、`zhipu`(智谱 GLM)、`moonshot`(月之暗面 Kimi),另外仍支持 `openai` / `anthropic` / `mock`。

**强烈建议同时加一行**:

```
STRICT_PROVIDER=true
```

否则 key 配错时系统会**静默回退到 mock 假数据**,你会以为在用真模型。开了这个开关就会直接报错。

> v2.0 起,无论从哪个目录启动后端,都会正确读到仓库根目录的 `.env`(以前从 `backend/` 启动会读不到,导致**明明配了 key 却静默用 mock 假数据**)。
> `.env` 里的 `DATABASE_URL` 现在是本地 SQLite;Docker 部署时 compose 会注入自己的数据库地址并自动覆盖,无需改动。

## 2. v2.0 新增功能全览

### 2.1 元件库(全新页面)

**解决的问题**:以前 AI 给你出实验方案,不知道你实验室实际有什么;现在它知道。

**怎么用**:

1. 导航栏 → **元件库** → 选择你的元件清单 xlsx(如"127镜片统计")→ 导入
2. 系统会把每一行的**镀膜字符串拆解成结构化数据**。比如
   `S1:1064-1066HR, 1176-1180 T=20%`
   会被拆成两条记录:`S1 面 / 1064–1066nm / HR` 和 `S1 面 / 1176–1180nm / 部分透过 20%`
3. 导入完成会显示三个数字:**导入条目 / 镀膜段 / 待复核**

**关于"待复核"**:凡是系统读不懂或你自己写了"切向未知""不能确定是否镀膜"的行,都会进这个队列,**原始文字完整保留**。勾选筛选区的"待复核队列"就能只看这些。系统绝不会替你猜。

**筛选**:可以按 `波长 + 功能` 精确筛(这是数据库级查询,不是关键词搜索)。比如填 1064 + HR,只会给你在 1064nm 真正是高反的镜子——而不是"名字里带 1064"的镜子。

### 2.2 元件匹配(按需求找元件)

**解决的问题**:"我要一块 1064 高反、曲率 400、口径至少 25 的镜子,库里有吗?"

在元件库页面填需求 → 开始匹配。系统对**每一件**库存逐参数判定,输出三类结果:

- **入围 / 前沿**:能用。"前沿"= 在所有维度上没有被其他候选全面超越的那几个,是你真正该在里面挑的
- **需实测**:可能能用,但依据不足。会明确告诉你**要测什么**
- **淘汰**:硬伤。页面底部会给"淘汰原因分布",让你知道是曲率不对、口径不够,还是镀膜不匹配

**三态判定是这套系统的精髓**,举个真实例子:

> 你需要 1064nm HR,库里有块标称 **1123nm HR** 的镜子。
> 系统不会简单说"不匹配",也不会假装能用,而是:调用薄膜物理内核算出这类镀膜的典型阻带约 1007–1269nm → 1064 落在里面,距离边缘 57nm → 判定 **"可能能用,需实测"**,并注明这是基于标准膜系的**物理先验,不是这块镜子的实测曲线**,上台前请测反射率。

反过来,如果某块镜子标称 **R=85%** 而你要求 R≥99.5%,系统会**直接淘汰**并说明"标称反射率 85% < 需求 99.5%"——不会因为"它也叫 HR"就放行。

### 2.2.5 实验计划会自己把腔设计出来(v2.0 关键能力)

**你不需要先知道用什么镜子。** 生成实验计划时,LaserClaw 会先跑确定性物理内核:

- 你**给了**腔镜曲率 → 扫描腔长,给稳区和推荐几何
- 你**没给** → 它**自己搜索**:遍历候选曲率 × 腔长(上千到上万种组合),两级排序挑出可实际搭建的几何。
  **候选曲率优先取自你导入的元件库**——不会推荐你没有的镜子。

**排序不看 |m|,而是实测热透镜裕度。** 这一点很重要:线性腔 `m = 2·g₁g₂ − 1`,所以 |m| 小
既可能是短臂分支、也可能是近共心分支,后者极不耐热透镜。实测方式是在增益介质处插一片薄透镜、
扫描光焦度直到失稳,报出腔能承受多少屈光度。同一对 R=400mm 镜子:

| 腔长 | 冷腔 \|m\| | 实测可承受热透镜 |
|---|---|---|
| 120 mm | 0.012 | **4.4 D** |
| 685 mm | 0.016 | **0.6 D** |

两者按 |m| 看几乎一样"安全",实际差 7 倍——所以旧的 |m| 判据被废弃了。

算出的数字会作为**权威数值**写进计划正文。真实例子(用户只说"想搭 808 泵浦 Nd:YAG 1064、
腔内 LBO 倍频到 532、输出 >1W,我只有库存里这几片镜子"):

> 推荐 R1=**R=500mm**、R2=**平镜**,腔长 **85.0mm**;冷腔束腰 **w0=0.24948mm**;
> 热透镜裕度 **8.3 D**(即 f≥120.5mm 时仍稳定)。
> 元件摆位:M1 @ **0.0mm** → 晶体入口 **20.0mm** → 晶体出口 **30.0mm** → M2 @ **85.0mm**。
> LBO type-I 1064→532 相位匹配:xy 面 **θ=90.0°, φ=11.36°**(另有 xz 面解 θ=32.48°)。
> 搜索空间:实验室库存曲率,评估 1413 种几何,其中 552 种稳定。

搜索过程可审计:结果里会带**评估了多少种几何、多少种稳定、备选方案、评分拆解
(模式惩罚 / 热稳健性惩罚各占多少)、排序目标函数、以及仍未纳入的因素**——
泵浦光斑与基模的重叠(模式匹配)、镀膜损耗、热透镜的像散与高阶项,这些仍需你上台核实。

### 2.3 物理计算模块(4 个)

在**案例 → 模块** tab,下拉框分成"测量分析"和"物理计算"两组。物理计算这 4 个都是纯公式,不经过大模型:

#### 谐振腔设计(cavity_design)
给腔镜曲率和晶体参数,它扫描腔长找出**稳定区间**,按你的目标束腰推荐腔长,并给出**每个元件从 M1 起的毫米级摆放位置**和各面光斑大小。

参数可以**完全留空**——会自动读案例参数。也可以填:
```json
{"R1_mm":"flat","R2_mm":500,"L_scan_mm":{"start":100,"stop":600,"step":10},"target_waist_mm":0.25}
```

#### 相位匹配(phase_match)
算 SHG/SFG 的相位匹配角与走离,支持 BBO / LBO / KTP / BiBO。
```json
{"crystal":"lbo","lambda1_nm":1064,"pm_type":"I"}
```
和频(如 1064+532→355)加一个 `"lambda2_nm":532` 即可。

#### 镀膜评估(coating_tmm)
三种模式:知道膜系 → 精确算;有厂商曲线 → 直接用;**只有标称波长 → 给诚实的原型估计**(带阻带区间、置信度、"建议实测"标记)。
```json
{"nominal":{"function":"HR","design_wavelength_nm":1123},"query_wavelengths_nm":[1064]}
```

#### 元件匹配(component_match)
就是 2.2 的能力,挂在案例里,结果会存进案例的审计轨迹。

### 2.4 功率曲线(v2 新增的测量模块)

**这是你日常最常用的测量**:不同泵浦功率下的输出功率。

**怎么用**:加一个"功率曲线"模块 → 上传两列数据文件(泵浦, 输出),支持 `.csv` / `.txt` / `.tsv`,逗号/制表符/空格分隔都行。或者在参数里内联:
```json
{"output_coupler_T_pct":5,"label":"T=5% 输出镜","data":{"pump":[...],"output":[...]}}
```

**它会自动算出**:
- **阈值泵浦功率**和**斜率效率**(自动识别线性区,用整段折线拟合,不会被数据尾巴带偏)
- 带坐标刻度、实测数据点、阈值标记的拟合图

**跨曲线分析(重点)**:如果你给同一个案例测了**多个不同输出镜透过率**的曲线,并在参数里标了 `output_coupler_T_pct`,系统会自动做:
- **Findlay-Clay 分析** → 反推**腔内往返损耗**
- **Caird 分析** → 反推**本征斜率效率**

也就是说,你日常的例行测量数据,直接就能算出腔内损耗——这是以前要手动画图拟合才能得到的量。

**关于警告**:如果数据不是典型的阈值曲线(比如高低泵浦段斜率不一致 = 热翻卷),系统会**明确警告**而不是给你一个漂亮但错误的阈值。看到警告请认真对待。

### 2.5 Agent 现在会真的调用工具

以前在 Agent 里说"设计个腔",它会写一段文字。现在:

> 你说:**"帮我设计一个谐振腔,扫描腔长找到稳区,算出束腰和元件摆放位置"**
>
> 系统:识别意图 → 制定 4 步计划 → 检索知识库 → **调用腔设计工具真算** → 结果+引用存档

聊天里会显示三种标签:**路由到哪个工具**、**任务编号与状态**、**📎 引用了哪些文档**。案例的 Agent tab 里能看到完整轨迹:每一步、每个工具调用、耗时多少毫秒。**全程可回放、可审计。**

也可以在案例的 Agent tab 里直接从下拉选模式(谐振腔设计/相位匹配/镀膜评估/元件匹配/功率曲线分析等)。

## 3. 典型工作流:从零搭一个 1064 倍频腔

1. **新建案例** —— 填标题、腔型、目标。参数里可以先写上 `wavelength_nm`、`R1_mm`、`R2_mm` 等(保存后会自动跳到案例详情页)
2. **模块 → 谐振腔设计** —— 参数留空直接运行 → 拿到稳定区间、推荐腔长、元件摆位
3. **元件库 → 元件匹配** —— 用第 2 步得到的曲率去库里找镜子 → 看哪些能用、哪些需实测
4. **模块 → 相位匹配** —— 确认倍频晶体的切角
5. **模块 → 镀膜评估** —— 核查候选镜子在 1064/532 各波长的表现
6. 上台搭建,把"需实测"清单上的项目测掉
7. **模块 → 功率曲线** —— 传测量数据,拿阈值和斜率效率;换个输出镜再测一条 → 自动出腔内损耗
8. **Agent → 生成实验报告** —— 所有模块结果和引用都在案例里,报告有据可依

## 4. 必须知道的边界(诚实清单)

这些不是 bug,是明确标注的适用范围:

- **双轴晶体相位匹配**(LBO/KTP/BiBO)用主平面近似,标注为 `medium` 置信度。下单前请和厂商确认切角
- **标称镀膜的阻带估计**是基于"标准膜系"的物理先验,**不是你那块镜子的实测曲线**。凡是标了"需实测"的,上台前请真的测
- **腔内有晶体时,束腰的"位置"是光程坐标**(尺寸精确)。要物理位置请看各面光斑列表
- **系统不控制任何硬件**。它是工作流与计算助手,不是控制系统
- **LLM 生成的文字部分**(实验计划、排故建议、报告)仍是启发式的,需要你判断。但**所有数字**来自确定性计算

## 5. 常见问题

**Q:参数框必须写 JSON 吗?**
不必。物理计算模块留空就能跑(自动读案例参数)。要覆盖时,点"参数示例"折叠区抄一条改。

**Q:导入元件库提示"需要 reviewer 权限"?**
在请求头带 `x-user-role: reviewer`,或本地演示模式下直接可用。生产部署请开 `REQUIRE_AUTH=true` 并配好用户。

**Q:元件库里"待复核"的行怎么办?**
那是系统读不懂或你原表就标了"未知"的行。原始文字都在,你可以在原 xlsx 里补全后重新导入(同名文件会覆盖旧数据)。

**Q:功率曲线要几条才能算腔内损耗?**
至少 2 条不同输出镜透过率的曲线。但 2 条时 R²=1 是数学必然、没有意义,系统会提示你"建议再测一组"。3 条起结果才可信。

**Q:界面能切英文吗?**
右上角 EN 按钮,全站双语。
